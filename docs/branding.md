# Название приложения и технические имена

Финальное название проекта — **Стечение**. Единый источник названия для интерфейса — корневой `branding.json`, поле `name`: доступное имя ссылки на главную, HTML title и meta description. После изменения перезапустите Vite или пересоберите frontend.

Четыре предоставленных PNG сохранены без изменения в `frontend/public/images/brand/`:

- `stechenie-logo-on-dark.png` — полный светлый логотип для тёмной шапки всех страниц.
- `stechenie-logo-on-light.png` — полный тёмный логотип для светлого подвала.
- `stechenie-mark-on-light.png` — отдельный знак для светлой вкладки и иконки Apple.
- `stechenie-mark-on-dark.png` — отдельный знак для тёмной вкладки.

Логотип содержит название: отдельная текстовая подпись рядом не дублируется. `Brand` сохраняет доступное имя ссылки «Стечение — на главную». Прозрачные вертикальные поля полного логотипа скрывает `object-fit: cover`; сами PNG не изменены. Светлую и тёмную иконку вкладки выбирает браузер по `prefers-color-scheme`.

Для замены брендинга тесты и сборка не запускались по просьбе пользователя. Исторические проверки ниже относятся к предыдущему изменению конфигурации, а не к этим логотипам.

Технические имена нейтральные: Java-пакет `ru.sport`, точка входа `SportApplication`, Maven artifact `sport-hub-backend`, npm package `sport-frontend`, Compose-проект `sport`, префикс mock localStorage `sport.mock`. Смена названия приложения не требует менять пакеты, БД, API или хранилища.

## Обновление уже запущенного сервера

Существующая PostgreSQL не переименовывается и не очищается. Перед первым запуском обновлённого Compose сохраните резервную копию и укажите в локальном `backend/.env` **фактические существующие** значения `DB_NAME`, `DB_USER`, `DB_PASSWORD` и `POSTGRES_VOLUME`. Имя текущего volume можно узнать через `docker volume ls` и `docker inspect` контейнера БД. Для новой установки значения по умолчанию нейтральные.

Остановите прежний Compose-проект без удаления его volume, затем запустите новый, указав сохранённый volume и прежние реквизиты. Не выполняйте `down -v`. Переменные POSTGRES_* задают начальную конфигурацию только для пустого volume; они не переименовывают существующую БД или пользователя. Для отдельного запуска Java по-прежнему используйте `DB_URL`, `DB_USER`, `DB_PASSWORD`.

Миграции Flyway, пользовательские UUID и бизнес-данные не изменяются. Демо-площадки проверяются также по имени и автору, поэтому обновлённый namespace seed не создаёт их повторно в прежней БД. Имя служебного демо-администратора приводится к нейтральному при включённом демо-режиме. Пользовательские записи и тексты не переписываются.

Mock-режим использует новый нейтральный префикс localStorage. Прежние локальные демо-данные остаются в браузере, но новая версия их не читает. Это не влияет на данные настоящего сервера.

История Git и внешнее имя репозитория не переписываются. В исходных требованиях PDF сохраняются оригиналы организаторов конкурса.

## Проверки изменения

- При предыдущем переименовании проверялись отслеживаемые текстовые файлы и пути; название для интерфейса было вынесено в `branding.json`.
- `mvn verify`: 78 тестов; дополнительно новый сценарий повторного seed проверен на H2 и PostgreSQL. PostgreSQL: основные сценарии и карта проходят; UUID существующих демо-площадок сохраняются, дубликатов нет. Flyway-миграции не изменены.
- Frontend: lint, production build, проверка генерации API и согласованности контракта проходят. Vitest: 328 из 333 проходят. Пять ошибок WebCrypto в signup воспроизведены на чистом `master` в том же окружении.
- Playwright: 19 из 24 проходят, включая создание встречи, гостевой профиль, каталог, переключение ролей, клавиатуру и ширины 320/375/768/1024/1440 px. Заголовок страницы и доступное имя логотипа берутся из конфигурации. Пять прежних сценариев редактирования профиля не раскрывают блок дополнительной ссылки на аватар и ждут скрытое поле; код формы в этой задаче не менялся.
