# Общая карта: Wi‑Fi и сервер

Все браузеры обращаются к `/api/v1` на адресе открытого сайта. Сервер пересылает запросы Java API, а Java вызывает Geoapify с одним серверным `GEOAPIFY_API_KEY`. IP посетителя и его `localhost` для геокодинга не используются. Подложка OpenFreeMap загружается браузером из интернета.

## Сейчас: компьютер друга и общий Wi‑Fi

На компьютере, где запускается backend, задайте `GEOAPIFY_API_KEY` в `backend/.env`. Сам файл не хранится в Git: при переносе репозитория на другой компьютер ключ нужно настроить там отдельно. Для обновления запущенного Compose-контейнера из `backend/`:

```sh
docker compose up -d --force-recreate backend
```

Если backend запускается без Docker, передайте ключ переменной окружения процессу Java: [инструкция](../../backend/README.md#подключение-api-ключа).

На том же компьютере:

```sh
cd frontend
npm ci
npm run dev -- --host 0.0.0.0
```

Остальные устройства открывают `http://IP_КОМПЬЮТЕРА:5173`, например `http://192.168.1.20:5173`. Нужны одна сеть без изоляции клиентов и разрешённый входящий TCP 5173 в брандмауэре. Backend может оставаться на `127.0.0.1:8080`: Vite проксирует `/api/v1` и сохраняет общий адрес сайта для сессии и CSRF. Ключ и отдельный доступ к порту 8080 посетителям не нужны.

Если Java находится на другой машине, в `frontend/.env.local` задайте `API_PROXY_TARGET=http://IP_СЕРВЕРА:8080` и перезапустите Vite. Переменная относится к серверу Vite и не включается в браузерный код. `VITE_API_BASE_URL` оставьте `/api/v1`.

Карта, выбор точки, адресные подсказки и сохранение площадки работают через HTTP в локальной сети. Кнопка «Моё местоположение» зависит от разрешений браузера и защищённого контекста: для неё на чужом устройстве нужен HTTPS.

## Развёртывание сборки

Для фото категорий видов спорта внешний reverse proxy должен разрешать тело запроса до 4 МиБ (`client_max_body_size 4m` для Nginx). Web-контейнер уже содержит эту настройку. Изображения сохраняются в PostgreSQL и доступны всем устройствам по относительному адресу `/api/v1/sports/.../image`; отдельный файловый volume для них не нужен.

В репозитории есть frontend Dockerfile и Nginx: он отдаёт сборку, обслуживает прямые ссылки `/map`, `/events/...` и проксирует `/api/` в `backend:8080` с сохранением публичного Host, включая порт.

Из `backend/` на сервере после настройки `.env`:

```sh
docker compose -f compose.yaml -f compose.web.yaml up --build -d
```

Открывайте `http://IP_СЕРВЕРА:8090`. `WEB_PORT` и `WEB_BIND` задаются в `backend/.env`; по умолчанию это `8090` и `0.0.0.0`. Backend и PostgreSQL сохраняют существующие локальные привязки портов и том данных. При уже используемом имени Compose-проекта сохраняйте его (`-p имя`) во всех командах.

Для домена настройте HTTPS на внешнем reverse proxy и направьте весь сайт, включая `/api/`, в web-контейнер. Передавайте исходный `Host` с портом; в `backend/.env` задайте `PUBLIC_SCHEME=https` и `COOKIE_SECURE=true`, затем повторите команду Compose для пересоздания web и backend. `PUBLIC_SCHEME` задаёт публичный протокол для проверки Origin/CSRF в Java за TLS-прокси. HTTP в Wi‑Fi требует `PUBLIC_SCHEME=http` и `COOKIE_SECURE=false`. Frontend не нужно пересобирать при смене IP или домена. При внешнем TLS-прокси можно ограничить web-привязку `WEB_BIND=127.0.0.1`; прямой порт Java остаётся локальным.

Ключ задаётся только окружению backend. При ограничениях ключа в Geoapify разрешайте исходящий IP сервера, а не IP телефонов. На новом сервере перенесите настройку ключа; не копируйте его в Dockerfile, Nginx или `VITE_*`.

## Проверка на любом устройстве

Откройте `/api/v1/health` по общему адресу сайта: ожидается 200. На странице создания площадки введите город и адрес от трёх символов, выберите подсказку: появится точка. Клик по карте должен подставить адрес. Сохраните площадку и убедитесь, что она видна после обновления на другом устройстве.

Если `/geo/suggest` или `/geo/reverse` возвращает 503, проверьте ключ, ограничения и доступ backend к Geoapify; если `/api/` возвращает 502 — соединение прокси с Java. Ключ не нужен для ручного выбора точки.
