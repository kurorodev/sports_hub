## Текущее состояние

Shell/session, каталог, создание личной встречи и OPEN-регистрация работают на сетевых моках. Java не интегрирован; DTO требуют сверки с общим OpenAPI. Следующий функциональный срез — S4: заявки с одобрением организатора.

## Как поддерживать документы

- Подробности хранятся в соответствующем документе; `frontend/README.md` содержит быстрый запуск и ссылки.
- При добавлении документа обновляйте это оглавление. Используйте относительные ссылки, работающие в GitHub и в локальном checkout.
- Фиксируйте результаты проверок с датой, режимом mock/Java и ограничениями в `QA.md`.
- Вопросы к общему контракту записывайте в `API_REVIEW.md`; временные mock-модели не считаются утверждённым API.

Эту папку и `frontend/README.md` можно коммитить вместе с фронтендом. Локальный `AGENTS.md` не входит в комплект документации и не переносится сюда. Корневые документы команды и `contracts/` остаются отдельными источниками требований.
