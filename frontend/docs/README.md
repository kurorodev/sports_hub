## Текущее состояние

Shell/session, каталог, создание личной встречи, OPEN-регистрация, APPROVAL-заявки, публичное обсуждение, допуск организаций с публикацией и модерация подключены к Java и PostgreSQL. S1–S6 проверены через браузер на 375/768/1440 px. DTO генерируются из `backend/contracts/openapi.yaml`; моки остаются отдельным режимом. Далее — общая приёмка и подготовка развёртывания, затем P1/P2. Ограничение показа автору причины скрытия комментария зафиксировано в API_REVIEW.

Последнее обновление добавляет личный/публичный профиль и редактирование, регистрацию отдельного демопользователя и ввод/отображение условий участия. Ссылки на организатора работают в каталоге, деталях и административной карточке. Backend регистрации объединён с веткой `frontend`.

## Как поддерживать документы

- Подробности хранятся в соответствующем документе; `frontend/README.md` содержит быстрый запуск и ссылки.
- При добавлении документа обновляйте это оглавление. Используйте относительные ссылки, работающие в GitHub и в локальном checkout.
- Фиксируйте результаты проверок с датой, режимом mock/Java и ограничениями в `QA.md`.
- Вопросы к общему контракту записывайте в `API_REVIEW.md`; временные mock-модели не считаются утверждённым API.

Эту папку и `frontend/README.md` можно коммитить вместе с фронтендом. Локальный `AGENTS.md` не входит в комплект документации и не переносится сюда. Корневые документы команды и `contracts/` остаются отдельными источниками требований.
