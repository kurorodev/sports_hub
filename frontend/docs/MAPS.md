# Карты и выбор места

`/map` показывает два независимых слоя: будущие опубликованные мероприятия с координатами и спортивные площадки. Фильтр вида спорта и bbox входят в query key; запросы отменяются через AbortSignal, окно обновляется через 300 мс после перемещения. Площадки перечитываются каждые 45 секунд при открытой странице. Неполная выдача отмечается просьбой приблизить карту. Список под картой доступен с клавиатуры и при недоступной подложке.

Начальная область — Самара, явно помеченная как демо-регион. «Моё местоположение» вызывает браузерную геолокацию только по нажатию. Поиск города/адреса использует тот же backend-прокси. Гостю доступны чтение и переход на вход с возвратом `/login?next=map`.

`shared/ui/LocationPicker` — управляемое поле `Location`. Оно собирается с RHF через Controller в создании мероприятия и площадки. Подсказки имеют debounce 350 мс, клавиатурное управление и выбор всех полей одним изменением. Ручная правка после подсказки очищает обе координаты. Клик/перетаскивание метки сохраняет честную точку, reverse заполняет адрес. При отсутствии адреса город и адрес заполняются вручную; поздний reverse после редактирования игнорируется. Без геокодера событие можно создать вручную без координат; площадке точка обязательна.

Карта и её библиотека загружаются по необходимости. Используется Leaflet с OSM-тайлами и видимой атрибуцией. Поставщик подложки заменяется через `VITE_MAP_TILE_URL` и `VITE_MAP_TILE_ATTRIBUTION` в frontend env. Пользовательские названия и адреса отображаются React-текстом. HTML-маркеры содержат только фиксированные символы, без пользовательских данных.

Оценки загруженности субъективны: LOW — мало людей, MEDIUM — умеренно, HIGH — много, UNKNOWN — нет актуальных данных. Число людей не задаёт цвет. Цвет продублирован текстом. Источник истины — сервер: свежими считаются последние оценки каждого пользователя за 90 минут, итог — верхняя медиана; на границе срока данные уже устарели. Клиент скрывает истёкший цвет до обновления с сервера. Повторная отправка одним пользователем на площадку разрешена через 10 минут. Изменения интерфейса подтверждаются после HTTP 201, ошибки сохраняют ввод.

## Запуск

```sh
cd frontend
npm ci
npm run dev       # Java на :8080, frontend :5173
# либо:
npm run dev:mock
```

Для реальных адресных подсказок задайте `GEOAPIFY_API_KEY` только в backend env и перезапустите backend. При отсутствии ключа `/geo/*` отвечает 503, `/map/*` продолжает работать. Ключ не нужен для самой карты. Настройка API: [backend/README.md](../../backend/README.md#карты-и-геокодинг).

В mock-режиме адресный справочник содержит одну проверенную точку: «Самара, площадь Куйбышева», [53.195561, 50.101022](https://www.wikidata.org/wiki/Q4365616). Это фиксированная демонстрационная подсказка, а не настоящий геокодер. Reverse возвращает её адрес только в непосредственной близости, для других точек — null. Площадки с пометкой «условный объект» вымышлены; не считайте их справочником реальных спортивных сооружений. Фикстуры показывают LOW/MEDIUM/HIGH и устаревший UNKNOWN. Новые площадки и отчёты хранятся отдельно в `dvizh.mock.map.v1`; авторы не возвращаются в публичных ответах.

## Проверка

```sh
npm run api:check
npm run typecheck
npm run lint
npm test -- --maxWorkers=2
npm run build
npm run build:mock
npm run test:e2e -- --workers=2
# При запущенном Java/PostgreSQL:
npm run test:e2e:api
```

Vitest проверяет координаты, debounce/клавиатуру, stale reverse, ручной fallback, bbox, TTL, медиану, CSRF, cooldown и фильтрацию мероприятий. `e2e/maps.spec.ts` проверяет создание события с точкой → маркер → ту же страницу события; добавление площадки → оценку → 429; независимость слоёв, возврат с входа и ширины 320/375/768/1024/1440. Браузерные тесты блокируют внешний сервер тайлов; бизнес-запросы проходят через MSW, подложка проверяется отдельно. В real-режиме используются те же типы и маршруты без автоматической подмены ошибочного API.

Ограничения MVP: нет кластеризации, модерации площадок или глобальной геоаналитики. Окно не больше 10° на ось, 300 объектов слоя по умолчанию. При совпадающих координатах объекты доступны через список и переключение слоёв. `validUntil` — ближайшее истечение среди оценок агрегата; после него медиана может измениться и требуется перечитать сервер.

Политики и API поставщиков: [Geoapify autocomplete](https://apidocs.geoapify.com/docs/geocoding/address-autocomplete/), [reverse](https://apidocs.geoapify.com/docs/geocoding/reverse-geocoding/), [OSM tiles](https://operations.osmfoundation.org/policies/tiles/). Публичный Nominatim не используется. OSM-тайлы предназначены здесь для небольшой демонагрузки; для большого трафика настройте подходящего поставщика и его атрибуцию.

Для `test:e2e:api` backend должен разрешать Origin `http://127.0.0.1:5174` через `CORS_ORIGINS`. Новые `e2e/api/maps.spec.ts` проверяют настоящий Java/PostgreSQL без service workers: событие с точкой при недоступном reverse и сохранение LOW новой площадки после отчёта. Этот набор предполагает пустой `GEOAPIFY_API_KEY`, чтобы воспроизводимо проверить ручной fallback; успешный ответ поставщика проверяется backend-тестами с подменённым HTTP-клиентом. Живое обращение к Geoapify без ключа не проверено.
