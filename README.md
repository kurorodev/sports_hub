# Стечение

**Веб-приложение для поиска спортивных встреч, совместных занятий и общения с участниками.** Пользователь выбирает мероприятие, записывается, обсуждает детали и следит за своими участиями. Организация публикует встречи от своего имени после одобрения, администратор управляет модерацией и поддержкой.

Этот README — инструкция для запуска проекта с нуля: на своём компьютере, для друзей по Wi-Fi и на сервере с доменом. **Для основного способа запуска нужны только Git и Docker с Compose.** Java, Maven, Node.js и PostgreSQL устанавливаются внутри контейнеров.

> Для полноценного поиска адресов и определения адреса по выбранной точке нужен собственный **API-ключ Geoapify**. Подключите его по разделу [«Карта и API-ключ»](#maps). Без ключа подложка карты открывается, но автоматическое заполнение адресов не работает; остаётся ручной ввод.

## Что установить

| Инструмент                 | Для чего нужен                                                    | Где взять                                                                       |
| -------------------------- | ----------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| Git                        | Скачать репозиторий и получать обновления                         | [git-scm.com](https://git-scm.com/downloads)                                    |
| Docker с Docker Compose v2 | Собрать и запустить приложение и базу                             | [Официальная установка Docker](https://docs.docker.com/get-started/get-docker/) |
| Современный браузер        | Открыть приложение; для интерактивной карты нужна поддержка WebGL | Chrome, Edge, Firefox или Safari                                                |

На Windows и macOS проще установить **Docker Desktop**, затем запустить его и дождаться готовности. На Linux можно использовать Docker Engine с плагинами Compose и Buildx. Если на Windows установщик предлагает WSL 2, завершите его настройку по инструкции Docker.

Проверка в терминале:

```text
git --version
docker --version
docker compose version
docker info
```

Последняя команда должна получить ответ от Docker Engine. Если клиент установлен, но Docker не запущен, сборка не начнётся.

Первая сборка скачивает образы и зависимости из Docker Hub, Maven Central и npm registry. Нужен доступ в интернет; первый запуск может занять несколько минут. При нехватке памяти увеличьте лимит Docker Desktop и повторите сборку. Фиксированный минимальный объём памяти проектом не установлен.

## Быстрый запуск: всё в Docker

### 1. Скачайте актуальный master

```sh
git clone --branch master https://gitverse.ru/hackrus.experts/cr-pr-final-2026_tsirs_samarskaya_oblast_16.git sport-hub
cd sport-hub/backend
```

Имя локальной папки специально задано как `sport-hub`, чтобы дальнейшие команды были одинаковыми у всех. Для закрытого репозитория потребуется доступ в GitVerse. Способ авторизации возьмите из интерфейса сервиса; пароль или токен не вставляйте в URL клонирования и README.

### 2. Создайте файл настроек

На Linux/macOS или в Git Bash:

```sh
cp .env.example .env
```

В Windows PowerShell:

```powershell
Copy-Item .env.example .env
```

Команда нужна **только при первом запуске**. Если `backend/.env` уже существует, сохраните свои настройки, а не заменяйте файл примером.

Сохраните файл именно как `.env`, а не `.env.txt`. Откройте `backend/.env` в редакторе. Для демонстрации оставьте значения из `.env.example` и заполните строку:

```dotenv
GEOAPIFY_API_KEY=ВСТАВЬТЕ_СВОЙ_КЛЮЧ
```

Замените весь текст справа от `=` настоящим ключом, без пробелов и кавычек. Как его получить — в [следующем разделе](#maps). Не публикуйте заполненный `.env`: он исключён из Git.

Для основного запуска также добавьте в этот файл:

```dotenv
WEB_PORT=8090
WEB_BIND=0.0.0.0
PUBLIC_SCHEME=http
CORS_ORIGINS=http://localhost:8090,http://127.0.0.1:8090,http://localhost:3000,http://localhost:5173
```

`CORS_ORIGINS` в файле должна быть одна строка: замените существующую, а не создавайте несколько одинаковых переменных.

### 3. Запустите приложение

**Из папки `sport-hub/backend`:**

```sh
docker compose -p sport -f compose.yaml -f compose.web.yaml up --build -d
```

Поднимаются три сервиса:

- `db` — PostgreSQL с постоянным хранилищем;
- `backend` — Java API; при старте Flyway автоматически применяет миграции;
- `web` — собранный React-интерфейс и Nginx, который также передаёт запросы `/api/` на backend.

Java, Node.js и Maven на компьютере для этого способа запуска не нужны. Одного `compose.yaml` недостаточно для интерфейса: **в команде должны быть оба файла**.

### 4. Проверьте готовность и откройте сайт

```sh
docker compose -p sport -f compose.yaml -f compose.web.yaml ps
```

Дождитесь состояния `healthy` у БД и отсутствия постоянных перезапусков backend. Сразу после создания контейнеров API ещё может запускаться.

Проверка с ожиданием:

```sh
curl --fail --retry 40 --retry-delay 3 --retry-connrefused http://localhost:8090/api/v1/health
```

В Windows PowerShell используйте `curl.exe` вместо `curl`. Ожидается JSON с `"status":"UP"`, `"service":"sport-backend"` и версией приложения.

**Откройте [http://localhost:8090](http://localhost:8090).**

| Адрес на вашем компьютере             | Назначение                                                                                 |
| ------------------------------------- | ------------------------------------------------------------------------------------------ |
| `http://localhost:8090`               | Приложение для пользователя                                                                |
| `http://localhost:8090/api/v1/health` | Проверка API и подключения к БД через тот же адрес, что использует интерфейс               |
| `http://localhost:8080/api/v1/health` | Прямая проверка backend                                                                    |
| `http://localhost:8080/openapi.yaml`  | Контракт API в YAML; отдельный Swagger UI не требуется и не предоставляется этим маршрутом |
| `localhost:5432`                      | PostgreSQL для локальных инструментов; это не адрес сайта                                  |

Если страница открылась, но API отвечает `502`, подождите завершения запуска backend и обновите её. Подробная диагностика — [ниже](#troubleshooting).

## Карта и API-ключ Geoapify

### За что отвечает ключ

| Компонент                       | Как работает                                                                            | Нужен ли ключ                                         |
| ------------------------------- | --------------------------------------------------------------------------------------- | ----------------------------------------------------- |
| Подложка карты                  | MapLibre GL JS и стиль OpenFreeMap                                                      | Нет; нужен доступ браузера к источникам карты         |
| Адресные подсказки              | Geoapify Address Autocomplete; при отсутствии результатов используется Geocoding Search | **Да**                                                |
| Адрес по клику на карту         | Geoapify Reverse Geocoding                                                              | **Да**                                                |
| Текущая геопозиция и расстояние | Разрешение браузера на геолокацию                                                       | Ключ Geoapify не нужен; требуется HTTPS или localhost |

Следовательно, видимая карта ещё не означает, что геокодирование настроено. Для полноценного выбора адреса подключите ключ. При отказе геокодера интерфейс позволяет вручную указать адрес и подтвердить выбранную точку; у площадки координаты обязательны.

### Как создать ключ

1. Откройте [Geoapify MyProjects](https://myprojects.geoapify.com/), зарегистрируйтесь и войдите в аккаунт.
2. Создайте проект кнопкой **Create a project**. Название можно выбрать произвольное, например `sport-local`.
3. Откройте проект и раздел **API Keys**. Первый ключ создаётся автоматически; при необходимости можно создать отдельный.
4. Скопируйте значение ключа. Подробности интерфейса: [официальное руководство Geoapify](https://www.geoapify.com/get-started-with-maps-api/).
5. Для проверки в панели поставщика доступны **Try API** и примеры запросов. В приложении используются Address Autocomplete, Geocoding Search и Reverse Geocoding.

Доступные лимиты и условия проверяйте в своём проекте Geoapify: приложение не предоставляет общий ключ и не управляет тарифом поставщика.

### Куда вставить ключ

В файл **`backend/.env`**:

```dotenv
GEOAPIFY_API_KEY=ВСТАВЬТЕ_СВОЙ_КЛЮЧ
```

Ключ использует сервер. Не добавляйте его в `frontend/.env*`, переменные `VITE_*`, исходники или параметры ссылки на сайт. Один настроенный backend обслуживает всех пользователей, в том числе подключённых по Wi-Fi; им не нужно получать собственные ключи.

После изменения `.env` **из `backend/`** пересоздайте backend и web:

```sh
docker compose -p sport -f compose.yaml -f compose.web.yaml up -d --force-recreate backend web
```

`docker compose restart` не подхватывает изменённые переменные окружения. Web также пересоздаётся, чтобы обновить адрес backend в Nginx после замены контейнера.

### Ограничения ключа у поставщика

Geoapify вызывается **с сервера**, а не из браузера. Для серверного ключа подходят ограничения по исходящему публичному IP сервера. Ограничения по HTTP Referrer или Origin сайта могут заблокировать такие запросы: Java-клиент не передаёт браузерные заголовки. При переезде сервера обновите разрешённый IP; домашний адрес может меняться. Настройка CORS у Geoapify не заменяет ограничения доступа. См. [правила API-ключей Geoapify](https://myprojects.geoapify.com/help/api-keys/).

### Как убедиться, что ключ работает

После запуска откройте в браузере:

```text
http://localhost:8090/api/v1/geo/suggest?q=Kuibyshev&city=Samara
http://localhost:8090/api/v1/geo/reverse?latitude=53.195561&longitude=50.101022
```

Успешный ответ — HTTP `200`: у поиска есть поле `items`, у обратного геокодирования — `location`. Пустой `items` может означать отсутствие подходящего адреса; это отличается от ошибки сервиса. В интерфейсе укажите город и начните вводить адрес, выберите подсказку, затем проверьте изменение адреса при выборе точки на карте.

HTTP `503` означает, что поиск адресов недоступен: проверьте наличие ключа, пересоздание backend, ограничения и лимит Geoapify, а также исходящий доступ сервера к `https://api.geoapify.com`. Приложение не раскрывает ответ поставщика с ключом пользователю.

## Первый вход и демонстрация

В примере `backend/.env` включено `DEMO_ENABLED=true`. При первом запуске создаются вымышленные аккаунты, мероприятия, организации и площадки. На странице **«Войти»** есть отдельный блок демо-входа — пароль для этих аккаунтов не нужен.

| Имя / аккаунт               | Идентификатор демо-входа | Что посмотреть                                                    |
| --------------------------- | ------------------------ | ----------------------------------------------------------------- |
| Алексей Спортов             | `athlete-a`              | Подтверждённые участия и ожидающие заявки                         |
| Мария Беговая               | `athlete-b`              | Запись, обсуждение, история мероприятий                           |
| Ирина Новая                 | `athlete-c`              | Отклонённая заявка и очередь ожидания                             |
| Денис Тренеров              | `coach`                  | Созданные личные мероприятия, рассмотрение заявок, отмена встречи |
| Представитель клуба «Темп»  | `org-approved`           | Публикация и управление мероприятиями одобренной организации      |
| Представитель «Новый старт» | `org-pending`            | Заявка организации на рассмотрении                                |
| Представитель «Вектор»      | `org-rejected`           | Отказ в допуске организации                                       |
| Администратор               | `admin`                  | Модерация, спортивные категории, сторис и поддержка               |

Идентификаторы — технические значения демоданных, а не пароли или выбираемые роли. Переключение аккаунта выполняется через страницу входа. Для двух независимых сессий откройте обычное и приватное окно браузера либо разные браузеры.

### Короткий маршрут знакомства

1. Откройте каталог и карту. На карте сначала показана демонстрационная область Самары.
2. Войдите обычным пользователем и запишитесь на будущую встречу со свободными местами.
3. Проверьте **«Мои мероприятия → Предстоящие»**; отмените участие с подтверждением и найдите его в **«Истории»**.
4. Создайте собственную встречу на будущую дату. Она появится в **«Мои мероприятия → Я организатор»**; отмена доступна создателю до начала.
5. Проверьте встречу с заявками: пользователь отправляет заявку, создатель рассматривает её со страницы мероприятия.
6. Войдите представителем организации, затем администратором и сравните доступные инструменты.
7. Откройте профиль, настройте тему и язык, заполните анкету для рекомендаций.

Можно зарегистрировать собственный аккаунт на `/register`, затем входить по никнейму и паролю на `/login`. Никнейм — 3–40 латинских букв, цифр, `_` или `-`; пароль — 8–128 символов. Самостоятельное назначение административных прав недоступно.

Даты демонстрационных встреч отсчитываются от первоначального наполнения БД. Через некоторое время они станут прошедшими: включите показ прошедших в каталоге или создайте новую встречу. Повторный запуск сохраняет данные и не переносит даты автоматически.

**Деморежим даёт вход без пароля, включая администратора.** Он предназначен для знакомства и демонстрации. Для обычного публичного приложения отключите его, как описано в разделе [о сервере](#server).

## Доступ по Wi-Fi с другого устройства

Используйте основной Docker-запуск. Отдельный backend на телефоне не нужен.

1. Подключите устройства к одной сети.
2. Узнайте локальный IP компьютера с Docker: `ipconfig` в Windows, `ip -4 addr` в Linux или настройки сети в macOS. Например, `192.168.1.50`.
3. В `backend/.env` оставьте `WEB_BIND=0.0.0.0`, `WEB_PORT=8090`, `PUBLIC_SCHEME=http`, `COOKIE_SECURE=false`. Добавьте origin устройства в строку разрешённых адресов:

   ```dotenv
   CORS_ORIGINS=http://localhost:8090,http://127.0.0.1:8090,http://192.168.1.50:8090
   ```

4. Из `backend/` примените настройки:

   ```sh
   docker compose -p sport -f compose.yaml -f compose.web.yaml up -d --force-recreate backend web
   ```

5. Разрешите входящие соединения на TCP-порт `8090` в локальном файрволе для своей сети.
6. На втором устройстве откройте **`http://192.168.1.50:8090`**, заменив IP на свой.

`localhost` на телефоне обозначает сам телефон, а не компьютер с Docker. Порты БД и backend наружу открывать не требуется: браузер обращается к web, а тот — к API внутри Docker.

Если включена изоляция клиентов Wi-Fi или используется гостевая сеть, устройства могут не видеть друг друга. После смены IP обновите ссылку и `CORS_ORIGINS`.

**Геолокация по обычному HTTP на сетевом IP может быть недоступна.** Для «Моего местоположения» и расстояний используйте HTTPS с доверенным сертификатом. `http://localhost` в браузере на компьютере — допустимое исключение. Отказ в геолокации не мешает смотреть карту и выбирать место вручную.

## Все настройки окружения

### Backend и Docker: `backend/.env`

Compose читает этот файл при запуске из `backend/`. Если запускаете команды из корня репозитория, укажите путь явно: `--env-file backend/.env`, а пути конфигураций — `-f backend/compose.yaml -f backend/compose.web.yaml`.

| Переменная         | По умолчанию / пример                         | Значение                                                                             |
| ------------------ | --------------------------------------------- | ------------------------------------------------------------------------------------ |
| `DB_NAME`          | `sport`                                       | Имя PostgreSQL-базы                                                                  |
| `DB_USER`          | `sport`                                       | Пользователь БД                                                                      |
| `DB_PASSWORD`      | `sport_local`                                 | Пароль БД; пример для локального запуска                                             |
| `POSTGRES_VOLUME`  | `sport_postgres_data`                         | Имя постоянного Docker volume                                                        |
| `DEMO_ENABLED`     | `true` в Compose                              | Демо-вход и первоначальное наполнение; `false` для обычного публичного использования |
| `GEOAPIFY_API_KEY` | пустое значение                               | Серверный ключ поиска адресов                                                        |
| `COOKIE_SECURE`    | `false`                                       | `true`, если пользователь открывает сайт по HTTPS                                    |
| `CORS_ORIGINS`     | `http://localhost:5173,http://localhost:3000` | Разрешённые origin через запятую, со схемой и портом, без пути и завершающего `/`    |
| `BACKEND_BIND`     | `127.0.0.1`                                   | На каком интерфейсе хоста доступен backend:8080                                      |
| `WEB_BIND`         | `0.0.0.0`                                     | На каком интерфейсе хоста доступен web                                               |
| `WEB_PORT`         | `8090`                                        | Порт сайта на хосте                                                                  |
| `PUBLIC_SCHEME`    | `http`                                        | Внешняя схема, передаваемая Nginx в backend; при HTTPS-прокси — `https`              |

Переменные, уже экспортированные в терминале, имеют приоритет над `.env` при подстановке Compose. Если значение неожиданно не применяется, проверьте окружение терминала.

В существующем PostgreSQL volume изменение `DB_USER`, `DB_NAME` или `DB_PASSWORD` **не переименовывает БД и не меняет пароль существующего пользователя**. Указывайте реальные реквизиты этой БД или выполняйте отдельную миграцию её настроек.

Имя volume задано явно: одного нового `-p` недостаточно, чтобы создать независимую БД второй копии. Для второго экземпляра задайте свой `POSTGRES_VOLUME` и свободные порты. Порты `5432` и `8080` в базовом Compose закреплены в `compose.yaml`; если они заняты, измените соответствующую левую часть привязки на хосте.

### Frontend: файлы `frontend/.env*`

| Переменная                               | Значение                                                                         |
| ---------------------------------------- | -------------------------------------------------------------------------------- |
| `VITE_API_MODE=real`                     | Настоящий backend; это основной режим                                            |
| `VITE_API_MODE=mock`                     | Локальная демонстрация на MSW без Java и БД                                      |
| `VITE_API_BASE_URL=/api/v1`              | Относительный адрес API; оставьте его для Docker и общего домена                 |
| `API_PROXY_TARGET=http://127.0.0.1:8080` | Адрес backend только для Vite-сервера при разработке                             |
| `VITE_MAP_STYLE_URL`                     | Необязательный URL MapLibre-стиля; по умолчанию используется OpenFreeMap Liberty |

Docker-сборка использует `.env.production`, Vite-разработка — `.env.real` или `.env.mock`. Локальные переопределения можно хранить в `.env.local` / `.env.real.local`, они исключены из Git. Переменные `VITE_*` попадают в клиентскую сборку и доступны пользователю; секреты туда не помещают.

Изменения frontend-настроек для Docker требуют **пересборки web**, а для Vite — перезапуска сервера. Произвольные frontend-переменные из `backend/.env` автоматически в сборку не передаются.

<a id="operations"></a>

## Остановка, обновление и сохранность данных

Все команды этого раздела выполняются **из `backend/`**, с теми же именем проекта и файлами Compose, что использовались при запуске.

| Действие                                 | Команда                                                                                          |
| ---------------------------------------- | ------------------------------------------------------------------------------------------------ |
| Статус                                   | `docker compose -p sport -f compose.yaml -f compose.web.yaml ps`                                 |
| Журналы                                  | `docker compose -p sport -f compose.yaml -f compose.web.yaml logs --tail=150 backend web db`     |
| Смотреть новые записи журналов           | `docker compose -p sport -f compose.yaml -f compose.web.yaml logs -f backend web`                |
| Остановить контейнеры                    | `docker compose -p sport -f compose.yaml -f compose.web.yaml stop`                               |
| Снова запустить                          | `docker compose -p sport -f compose.yaml -f compose.web.yaml up -d`                              |
| Удалить контейнеры и сеть, сохранив БД   | `docker compose -p sport -f compose.yaml -f compose.web.yaml down`                               |
| Применить изменённый `.env` к приложению | `docker compose -p sport -f compose.yaml -f compose.web.yaml up -d --force-recreate backend web` |

`Ctrl+C` при просмотре журналов завершает только просмотр. В режиме `up -d` приложение продолжает работать после закрытия терминала.

**Не используйте `down -v` или удаление volume, если хотите сохранить данные.** База содержит аккаунты, мероприятия, уведомления и другие пользовательские данные. Обычные `stop`, `down` и пересборка контейнеров сохраняют volume.

### Обновление до актуального master

Сначала сделайте [резервную копию](#backup). Из корня репозитория:

```sh
git status
git switch master
git pull --ff-only origin master
cd backend
docker compose -p sport -f compose.yaml -f compose.web.yaml up --build -d --force-recreate backend web
```

Перед переключением сохраните собственные изменения. `origin` должен указывать на репозиторий, из которого вы получаете обновления; адрес проверяется через `git remote -v`. `.env` не заменяйте примером. Новые миграции применяются автоматически; старые SQL-миграции и таблицу истории Flyway вручную не редактируйте.

В этой конфигурации используется один экземпляр backend, сессии хранятся в его памяти. После пересоздания backend потребуется войти снова; аккаунты и данные останутся в PostgreSQL.

<a id="server"></a>

## Размещение на сервере и HTTPS

Основной Docker-запуск подходит и для Linux-сервера. Для доступа только по IP можно открыть TCP-порт `8090` и использовать `http://IP_СЕРВЕРА:8090`; для геолокации и обычной эксплуатации настройте HTTPS.

### Вариант с доменом и Caddy

1. Установите Git и Docker, склонируйте репозиторий и создайте `backend/.env`, как в [быстром запуске](#quick-start).
2. Направьте DNS-запись домена на публичный IP сервера. Если есть AAAA-запись, IPv6 также должен вести на этот сервер. Откройте входящие TCP-порты `80` и `443`.
3. Установите Caddy по [официальной инструкции](https://caddyserver.com/docs/install) для своей ОС.
4. До первого запуска выберите собственный пароль БД. В `backend/.env` задайте настройки ниже, заменив `sport.example.org` своим доменом, а значение `DB_PASSWORD` — длинным случайным паролем:

   ```dotenv
   DB_PASSWORD=CHANGE_TO_A_LONG_RANDOM_PASSWORD
   DEMO_ENABLED=false
   WEB_BIND=127.0.0.1
   WEB_PORT=8090
   BACKEND_BIND=127.0.0.1
   PUBLIC_SCHEME=https
   COOKIE_SECURE=true
   CORS_ORIGINS=https://sport.example.org
   GEOAPIFY_API_KEY=ВСТАВЬТЕ_СВОЙ_КЛЮЧ
   ```

5. Для пакетной установки Caddy на Linux поместите в `/etc/caddy/Caddyfile`:

   ```caddyfile
   sport.example.org {
       reverse_proxy 127.0.0.1:8090
   }
   ```

6. Из `backend/` запустите/пересоздайте приложение:

   ```sh
   docker compose -p sport -f compose.yaml -f compose.web.yaml up --build -d --force-recreate backend web
   ```

7. Проверьте и примените конфигурацию Caddy:

   ```sh
   sudo caddy validate --config /etc/caddy/Caddyfile
   sudo systemctl enable --now caddy
   sudo systemctl reload caddy
   ```

8. Откройте `https://sport.example.org` и `https://sport.example.org/api/v1/health`.

Caddy получает и обновляет сертификат при корректном DNS и доступных портах. Условия описаны в [документации HTTPS](https://caddyserver.com/docs/automatic-https) и [руководстве reverse proxy](https://caddyserver.com/docs/quick-starts/reverse-proxy). Этот пример предполагает Caddy, установленный **на хосте**, а не в соседнем контейнере.

Запросы идут по цепочке: **браузер → Caddy HTTPS → web/Nginx → backend → PostgreSQL**. Сайт и `/api/` имеют один внешний origin. Не публикуйте отдельно PostgreSQL и Java API в интернет. Значение `PUBLIC_SCHEME=https` важно для корректной обработки внешнего адреса и cookie за прокси.

На сервере замените демонстрационный пароль БД до создания первого volume, подключите собственный ключ Geoapify и настройте резервные копии. Одной смены IP или домена в `.env` недостаточно для ограниченного ключа: проверьте также разрешённый исходящий IP в Geoapify.

### Демо-стенд и обычное приложение

- **Демо-стенд:** `DEMO_ENABLED=true`. Посетитель может войти в тестовые роли без пароля, включая администратора. Используйте вымышленные данные.
- **Обычное приложение:** `DEMO_ENABLED=false`. Регистрация и парольный вход продолжают работать; демо-вход и первоначальное демонаполнение выключены. На свежей БД пользовательские мероприятия создаются через интерфейс, а допуск организаций выполняет администратор.

Для назначения первого администратора зарегистрируйте собственный парольный аккаунт, затем владелец сервера может выполнить из `backend/`:

```sh
docker compose -p sport -f compose.yaml -f compose.web.yaml exec db psql -U sport -d sport
```

Замените `sport` реальными `DB_USER` и `DB_NAME`, если они отличаются. В открывшейся консоли PostgreSQL:

```sql
UPDATE users SET admin = true WHERE normalized_nickname = 'your-admin-nickname';
\q
```

Замените никнейм своим, в нижнем регистре и без `@`; ожидается `UPDATE 1`. Выйдите из аккаунта на сайте и войдите снова. Это действие владельца БД, оно не доступно обычным пользователям интерфейса. Выключение деморежима не удаляет уже созданные данные.

Для нескольких экземпляров backend нужны общее хранилище сессий и дополнительные настройки масштабирования; текущий Compose рассчитан на один экземпляр.

<a id="backup"></a>

## Резервная копия и восстановление

Из `backend/` создайте дамп в контейнере, затем скопируйте его на компьютер:

```sh
docker compose -p sport -f compose.yaml -f compose.web.yaml exec -T db sh -c 'pg_dump -Fc -U "$POSTGRES_USER" -d "$POSTGRES_DB" -f /tmp/sport-backup.dump'
docker compose -p sport -f compose.yaml -f compose.web.yaml cp db:/tmp/sport-backup.dump ./sport-backup.dump
```

Двоичный файл копируется без перенаправления потока PowerShell. Сохраните его вне контейнера и репозитория; он содержит пользовательские данные. Сохраните отдельно параметры подключения и ключи в защищённом месте. Для нескольких копий используйте разные имена дампов на компьютере.

**Восстановление заменяет содержимое целевой БД данными дампа.** Выполняйте его только для нужного экземпляра, предварительно сохранив его текущую копию:

```sh
docker compose -p sport -f compose.yaml -f compose.web.yaml stop backend web
docker compose -p sport -f compose.yaml -f compose.web.yaml cp ./sport-backup.dump db:/tmp/sport-backup.dump
docker compose -p sport -f compose.yaml -f compose.web.yaml exec -T db sh -c 'pg_restore --clean --if-exists --no-owner --no-acl -U "$POSTGRES_USER" -d "$POSTGRES_DB" /tmp/sport-backup.dump'
docker compose -p sport -f compose.yaml -f compose.web.yaml up -d
```

Для восстановления используйте совместимую версию приложения: после старта Flyway проверит историю и применит ещё не выполненные миграции.

<a id="development"></a>

## Запуск для разработки

Для просмотра готового приложения этот раздел не нужен.

### Backend в Docker, frontend через Vite

Понадобятся [Node.js](https://nodejs.org/en/download) **22.12+ в ветке 22.x** или совместимая более новая LTS-версия и npm. Версии зависимостей фиксирует `frontend/package-lock.json`; используйте `npm ci`.

Из корня репозитория, при уже созданном `backend/.env`:

```sh
docker compose --env-file backend/.env -p sport -f backend/compose.yaml up --build -d
cd frontend
npm ci
npm run dev
```

Откройте **`http://localhost:3000`**. Это порт Vite по умолчанию; основной Docker-сайт использует `8090`. Если нужен другой порт, например `5173`:

```sh
npm run dev -- --port 5173 --strictPort
```

Добавьте выбранный origin в `CORS_ORIGINS` и примените настройки backend. Vite проксирует `/api/v1` на `127.0.0.1:8080`. Если backend доступен по другому адресу, создайте `frontend/.env.real.local`:

```dotenv
API_PROXY_TARGET=http://127.0.0.1:8080
```

Если сам Vite запущен внутри контейнера, `127.0.0.1` означает этот контейнер: укажите адрес backend, доступный именно из его окружения. Для доступа по Wi-Fi браузер открывает IP компьютера с Vite и его порт; ключ карты по-прежнему остаётся в Java backend.

### Java без контейнера приложения

Понадобятся **JDK 21**, Maven 3.9.x и PostgreSQL 17.6. БД можно оставить в Docker. Из `backend/`:

```sh
docker compose -p sport -f compose.yaml -f compose.web.yaml stop backend web
docker compose -p sport -f compose.yaml up -d db
mvn verify
```

Затем задайте процессу Java переменные `DB_URL`, `DB_USER`, `DB_PASSWORD`, `DEMO_ENABLED`, `GEOAPIFY_API_KEY`, `COOKIE_SECURE`, `CORS_ORIGINS` и выполните:

```sh
mvn spring-boot:run
```

По умолчанию `DB_URL=jdbc:postgresql://localhost:5432/sport`, `DB_USER=sport`, `DB_PASSWORD=sport_local`, порт API — `8080`. Если нужен демо-вход, передайте `DEMO_ENABLED=true`. **Maven/Java не читают `backend/.env` автоматически:** задайте переменные в терминале или конфигурации запуска IDE. Изменения в `.env`, используемом Compose, сами по себе не меняют окружение Java-процесса.

Скрипт [backend/scripts/install-debian.sh](backend/scripts/install-debian.sh) помогает установить JDK/Maven/Docker только на Debian 13; он не является универсальным установщиком для других ОС. Скрипт [backend/scripts/start-local.sh](backend/scripts/start-local.sh) дополнительно вызывает историческую smoke-проверку, описанную ниже; для первого запуска используйте команды Compose из этого README.

### Только интерфейс без Java и PostgreSQL

Из `frontend/` после `npm ci`:

```sh
npm run dev:mock
```

Откройте `http://localhost:3000`. MSW перехватывает API-запросы; данные локальны для браузера, роли и данные отличаются от настоящего backend. Для этого режима не нужен Geoapify-ключ. Он подходит для знакомства с интерфейсом, но не заменяет проверку общего сервера и совместной работы пользователей.

Для возврата к настоящему API остановите Vite, запустите backend и выполните `npm run dev`. В real-режиме приложение не переключается на моки при недоступности сервера.

## Проверки и тесты

Минимальная проверка развёртывания: загрузилась главная, `/api/v1/health` вернул `UP`, работает вход, список спортивных категорий, создание будущей встречи и запись из другого аккаунта. Для карты отдельно проверьте два геомаршрута из [раздела о ключе](#maps).

| Команда и рабочая папка                  | Проверка                                                                          |
| ---------------------------------------- | --------------------------------------------------------------------------------- |
| `mvn verify` из `backend/`               | Сборка backend и тесты на H2                                                      |
| `mvn -Ppostgres-it verify` из `backend/` | Дополнительно PostgreSQL-интеграция через Testcontainers; нужен работающий Docker |
| `npm run build` из `frontend/`           | TypeScript и production-сборка интерфейса                                         |
| `npm run lint` из `frontend/`            | ESLint                                                                            |
| `npm test` из `frontend/`                | Frontend-тесты Vitest                                                             |
| `npm run api:check` из `frontend/`       | Соответствие сгенерированных типов OpenAPI-контракту                              |
| `npm run sports:check` из `frontend/`    | Синхронизация справочника спортивных категорий                                    |

Браузерные тесты из `frontend/`:

```sh
npx playwright install chromium
npm run test:e2e
```

На Linux Playwright может попросить установить системные зависимости: следуйте сообщению установщика (`npx playwright install --with-deps chromium` при наличии нужных прав).

Для проверки на реальном Java API сначала запустите backend с `DEMO_ENABLED=true`, добавьте `http://127.0.0.1:5174` в `CORS_ORIGINS` и примените настройки. Затем из `frontend/`:

```sh
npm run test:e2e:api
```

Playwright сам поднимает тестовый Vite на `5174` и ожидает API по `127.0.0.1:8080`. Проверки API создают и изменяют данные: запускайте их на отдельном демонстрационном экземпляре, а не на базе с важными пользовательскими данными.

В [backend/scripts/smoke.py](backend/scripts/smoke.py) осталась устаревшая проверка: скрипт ожидает причину снятия мероприятия в публичной карточке, хотя актуальный API передаёт её адресату в личных уведомлениях. Поэтому этот скрипт и вызывающий его `start-local.sh` могут завершиться ошибкой в финальном сценарии при работающем приложении. Для проверки развёртывания используйте health, вход и пользовательские действия выше; сам smoke-скрипт также изменяет демоданные.

<a id="troubleshooting"></a>

## Если что-то не работает

| Симптом                                                | Что проверить                                                                                                                                                 |
| ------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Cannot connect to the Docker daemon`                  | Запущен ли Docker Desktop / Docker Engine, есть ли у пользователя доступ к нему. `docker info` должен работать.                                               |
| `docker: 'compose' is not a docker command`            | Нужен Compose v2 — плагин `docker compose`. Старый отдельный `docker-compose` не является командой из этой инструкции.                                        |
| Ошибка скачивания образа или зависимостей              | Интернет, DNS, доступ к Docker Hub / npm / Maven Central. Это может быть ограничение сети, а не ошибка проекта.                                               |
| `port is already allocated` / `address already in use` | Заняты `8090`, `8080` или `5432`. Для сайта меняется `WEB_PORT`; привязки API/БД находятся в `compose.yaml`. После смены порта обновите URL и `CORS_ORIGINS`. |
| Контейнеры есть, но сайта нет                          | Подключён ли `compose.web.yaml`, есть ли сервис `web`, открываете ли вы `8090`, а не порт Vite.                                                               |
| Nginx отвечает `502 Bad Gateway`                       | Backend ещё запускается или завершился. Проверьте `logs backend db`; после замены backend пересоздайте `web`, чтобы обновить адрес upstream.                  |
| Ошибка пароля PostgreSQL                               | Значения `.env` должны совпадать с существующей БД. Новый пароль в файле не меняет пароль уже инициализированного volume.                                     |
| Ошибка Flyway / Hibernate validate                     | Проверьте логи и версию кода. Не удаляйте таблицу истории миграций; сохраните БД и выясните причину расхождения.                                              |
| Нет демоаккаунтов                                      | Для настоящего backend включите `DEMO_ENABLED=true` и пересоздайте его; в обычном режиме зарегистрируйте аккаунт с паролем.                                   |
| Не видны будущие демовстречи                           | Их даты уже прошли; включите прошедшие в каталоге или создайте новую встречу. Повторный старт даты не переносит.                                              |
| Вход сразу теряется по HTTP                            | Для локального HTTP нужно `COOKIE_SECURE=false` и `PUBLIC_SCHEME=http`. Не смешивайте `localhost` и `127.0.0.1` в одной сессии.                               |
| `403` при записи / сохранении                          | Для действий нужен вход и актуальный CSRF; обновите страницу. Проверьте внешний origin, `CORS_ORIGINS`, `PUBLIC_SCHEME` и корректность прокси.                |
| Главная работает, а обновление `/profile` даёт `404`   | При собственном размещении SPA нужен fallback на `index.html`. В `frontend/nginx.conf` он уже настроен.                                                       |
| Карта видна, но адрес не находится                     | Проверьте `GEOAPIFY_API_KEY`, пересоздание контейнера, ограничения и лимит Geoapify. Нужен ключ на backend, а не в `VITE_*`.                                  |
| `/geo/*` возвращает `503`                              | Нет рабочего ключа, поставщик недоступен, исчерпан лимит либо блокируется исходящий HTTPS. Карта и ручной ввод остаются доступны.                             |
| Пустая подложка карты                                  | Браузеру нужен доступ к OpenFreeMap и поддержка WebGL. Ключ Geoapify не исправляет недоступность картографического стиля.                                     |
| Встречи не видны на карте                              | Проверьте координаты, текущую область, дату и публикацию. Событие с ручным адресом без координат в каталоге есть, а на карте — нет.                           |
| Не работает «Моё местоположение»                       | Разрешение браузера, HTTPS/localhost и доступность геолокации. HTTP по IP в Wi-Fi обычно недостаточно.                                                        |
| `.env` изменён, поведение прежнее                      | Нужен `up -d --force-recreate backend web`. Для `VITE_*` — пересборка web. Проверьте также экспортированные переменные терминала.                             |
| Друг не открывает сайт по Wi-Fi                        | Используется IP компьютера с Docker, правильный порт, `WEB_BIND=0.0.0.0`, разрешён файрвол и выключена изоляция клиентов сети.                                |

Диагностика из `backend/`:

```sh
docker compose -p sport -f compose.yaml -f compose.web.yaml ps
docker compose -p sport -f compose.yaml -f compose.web.yaml logs --tail=150 backend web db
```

При обращении за помощью укажите ОС, способ запуска, адрес страницы, HTTP-статус и фрагмент ошибки. Не отправляйте `.env`, API-ключи, пароли, cookie и токены сессии. Полный вывод `docker compose config` тоже может содержать секреты; для проверки синтаксиса используйте `config --quiet`.
