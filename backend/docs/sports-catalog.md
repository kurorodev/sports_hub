# Справочник спортивных категорий

По решению владельца продукта от 20.10.2026 общий каталог закрыт для пользовательского ввода: **200 видов спорта из снимка ВРВС + одна категория «Другое»**. Это уточняет прежнюю трактовку S1: свой вариант активности по-прежнему сохраняется и доступен другому пользователю, но не создаёт общую категорию.

## Источник и границы актуальности

Источник: [опубликованный муниципальной спортивной школой Всероссийский реестр видов спорта на 7.10.2025](https://sshpgo.profiedu.ru/sveden/document), [исходный файл XLSX](https://sshpgo.profiedu.ru/file/download?id=415). Сохранены названия видов спорта и номера-коды всех четырёх разделов: признанные, общероссийские, национальные и прикладные. Спортивные дисциплины не превращаются в самостоятельные категории. Названия приведены из верхнего регистра к обычному написанию.

Файл получен 20.10.2026; SHA-256 исходника указан в `src/main/resources/sports-registry.json`. Доступный снимок не является подтверждением полного актуального состава ВРВС на октябрь 2026 года: прямое хранилище Минспорта при проверке вернуло HTTP 403. Проверять изменения следует по [странице Минспорта о ВРВС](https://www.minsport.gov.ru/activity/government-regulation/priznanie-vidov-sporta-i-sportivnyh-discziplin-vserossijskij-reestr-vidov-sporta/).

Снимок заморожен для миграции V3, его checksum проверяет Flyway. Обновление реестра требует нового снимка и следующей миграции; не заменять файл V3. Не добавлять виды спорта вручную из пользовательского текста. Во время запуска сеть к источнику не нужна.

## API и совместимость

- `GET /sports` возвращает только канонические категории, «Другое» идёт последним; `q` ищет по названию категории. У официальной записи `registryCode` содержит код ВРВС, `isCustom=false`; у «Другое» код `null`, `isCustom=true`.
- `EventCreate.sport={sportId}` выбирает справочную категорию. Существующая форма `{customName}` сохранена для совместимости транспорта, но теперь всегда означает активность категории «Другое». Сервер не создаёт `SportEntity` из запроса.
- `Event.customSportName` / `EventCard.customSportName` содержат название нестандартной активности. Оно отображается как текст события и участвует в поиске `q`/`sport`, но отсутствует в справочнике и общих фильтрах. Для официального выбора поле `null`.
- Миграция V3 переносит существующие события, площадки, предпочтения и связи организаций к каноническим категориям. «Бег» становится «Легкая атлетика»; неизвестные названия сохраняются у события в «Другое». Дубли связей объединяются; существующий уровень канонического предпочтения сохраняется.
- Старые строки спорта не удаляются: они становятся внутренними алиасами через `canonical_id`, скрытыми из `GET /sports`. Старый UUID разрешается в канонический на границах записи и фильтров. Миграция не удаляет события, регистрации, комментарии или пользователей.

## Frontend и моки

Реальный UI получает справочник из Java. Каталог использует полный select и короткий ряд быстрых фильтров; карта и создание получают те же данные. Для «Другое» форма запрашивает название активности. Созданное событие не добавляет вкладку/option с пользовательским названием.

Моки используют копию снимка, генерируемую из backend-источника: из `frontend/` выполнить `npm run sports:generate`, проверить `npm run sports:check`. Это данные моков, не второй реальный справочник. Типы API обновляются через `npm run api:generate`.

## Проверки

`mvn verify`: полный набор Java/H2, в том числе неизменность справочника после создания и перенос базы V2→V3 со старыми связями. `mvn -Ppostgres-it verify`: также PostgreSQL/Testcontainers и та же миграция. Frontend: `npm run sports:check`, `npm run api:check`, `npm run typecheck`, `npm run lint`, `npm test`, `npm run build`, `npm run test:e2e`, `npm run test:e2e:api`.

Ручной путь: выбрать официальный спорт → создать встречу → найти по категории. Затем выбрать «Другое», указать новый вариант → опубликовать → перезагрузить → найти другим аккаунтом в «Другое». Проверить сохранение названия в событии и отсутствие новой общей категории. Сверить каталог, карту и создание на 375/768/1440 px.
