# Сторис «Стечения»

Новости от администрации для всех вошедших пользователей, без подписок. Только ADMIN публикует и удаляет сторис. Публикация доступна ровно 24 часа: `expiresAt = createdAt + 24h`, оба поля назначает сервер. Срок не выбирается и не продлевается. Администратор может удалить публикацию раньше.

Сторис содержит заголовок (3–80 символов), необязательный текст (до 1000 символов) и необязательное изображение PNG/JPEG (до 2 МБ, до 4096×4096). Сервер проверяет содержимое изображения и перекодирует его, исходные метаданные не сохраняются. Видео и редактирование опубликованной сторис не входят в этот срез.

| Метод | Назначение |
| --- | --- |
| `GET /api/v1/stories` | Активные сторис от новых к старым, персональный `readAt`, серверный `asOf` |
| `POST /api/v1/admin/stories` | Публикация: `{title, text, imageData?}`; только ADMIN |
| `DELETE /api/v1/admin/stories/{storyId}` | Досрочное удаление; только ADMIN, повторное удаление идемпотентно |
| `POST /api/v1/stories/{storyId}/view` | Первый просмотр текущим пользователем; повторный запрос сохраняет первую дату |
| `GET /api/v1/stories/{storyId}/image` | Изображение активной сторис, `Cache-Control: no-store` |

Для всех методов требуется сессия, для изменений также CSRF. В момент `expiresAt` и позднее сторис отсутствует в ленте, а её изображение и регистрация просмотра возвращают 404. Досрочное удаление сразу закрывает эти же пути. Удаление не ограничено автором: управлять может любой ADMIN.

Миграция `V14__stories.sql`: метаданные в `stories`, бинарные изображения отдельно в `story_images`, личные просмотры в `story_views`. Поэтому лента не извлекает все бинарные файлы. Ограничение БД фиксирует 24 часа. Блокировка строки сторис сериализует просмотр и удаление; уникальная пара `(story_id,user_id)` исключает дубли. Истечение срока определяется при чтении, без зависимости от фонового задания. Просроченные записи остаются в БД недоступными; при ручном удалении бинарное изображение удаляется.

На frontend кружки показываются вошедшим пользователям на главной, под компактным заголовком и над поиском мероприятий. Пустая лента у обычного пользователя скрывается. Админ публикует кнопкой «Добавить» там же или в `/admin?section=stories`. Просмотр открывается по центру экрана в одном модальном окне: при переходе меняется только содержимое, фон и блокировка прокрутки сохраняются. Автоматическое переключение через 8 секунд; короткий тап по правой половине — вперёд, по левой — назад, на первой сторис левый тап остаётся на месте. Удержание ставит показ на паузу и не перелистывает при отпускании; вертикальная прокрутка текста не считается тапом. Также доступны кнопки, стрелки клавиатуры, свайп и Escape. Изображения предзагружаются при открытии главной и используются повторно для кружков и просмотра через blob URL в памяти текущего экрана; повторного HTTP-запроса при переходе нет. При смене аккаунта/уходе со страницы загрузки отменяются и blob URL освобождаются; удалённые сторис также исключаются из этого кэша. Если изображение ещё загружается, через 150 мс появляется небольшой индикатор по центру, без вспышки текстовой плашки. HTTP-ответ изображения сохраняет `Cache-Control: no-store`. Отметка просмотра отправляется после загрузки изображения; у текстовой сторис — при открытии. Отсчёт доступности использует серверный `asOf`, а не календарное время устройства. Активная лента обновляется раз в 30 секунд, локально просроченные сторис скрываются без ожидания обновления. При смене аккаунта приватный cache сбрасывается.

Моки используют те же пути, роли, CSRF, DTO и сроки. Публикации и личные просмотры хранятся в localStorage одного браузера. Это не обмен данными между устройствами; для него нужен Java API. Mock-проверка изображения ограничена форматом, сигнатурой и размером; полное декодирование и проверка разрешения выполняются Java. Квота localStorage может ограничить число изображений в mock mode.

## Ручная проверка

1. Войти как admin, открыть «Модерация → Сторис», создать текстовую сторис и отдельную сторис с PNG/JPEG. Проверить ошибки короткого заголовка, длинного текста и неподходящего файла.
2. Войти как USER A: обе сторис видны, кнопки публикации и удаления отсутствуют. Проверить паузу, продолжение, переключение, свайп, закрытие и возврат фокуса.
3. Просмотреть одну сторис, перезагрузить: отметка сохранена. Под USER B эта же сторис ещё не просмотрена.
4. Удалить сторис админом: она исчезает из ленты, прямой запрос изображения и отметка просмотра дают 404.
5. После 24 часов проверить исчезновение и 404 для изображения/просмотра. Проверить на 375/768/1440 px, в светлой и тёмной теме.

Для Java пересобрать backend существующей командой Docker Compose для вашей установки; применяется миграция V14. Не меняйте имя текущего Compose-проекта или volume ради этой функции. Frontend: `npm run dev` или `npm run dev:mock` из `frontend/`.

Добавлены `StoriesTest` и `PostgresStoriesTest`: роли/CSRF, запрет собственного срока, личные просмотры, граница ровно 24 часа, отзыв изображения при удалении, отказ для некорректного изображения. Тесты, typecheck, lint, сборка и браузерные проверки **не запускались** по просьбе пользователя. Типы пересозданы командой `npm run api:generate`. Код подключён к Java и MSW; выполнение сценария на Java/PostgreSQL ещё не подтверждено.
