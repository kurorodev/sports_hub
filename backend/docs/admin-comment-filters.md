# Фильтры комментариев администратора

В `/admin?section=comments` доступны поиск и выбор пользователя по никнейму, поиск и выбор мероприятия по названию, «Последние 10 комментариев» и «За последние 24 часа». Подсказки раскрываются прямо под полем с первой буквы: мероприятие ищется по названию, пользователь — только по никнейму `@user`, а не по имени/фамилии. Доступны выбор мышью и стрелками/Enter, закрытие Escape, сообщение об отсутствии совпадений и повтор поиска после ошибки. Мероприятия в подсказках доступны постранично. Выбранный пользователь и мероприятие показаны отдельно и снимаются крестиком независимо друг от друга. Выбранные условия сначала остаются черновиком: список комментариев и URL меняются только по кнопке «Применить фильтры». Применение сбрасывает страницу комментариев, сохраняет условия в URL; перезагрузка восстанавливает применённые фильтры. Повторное нажатие без изменений обновляет текущую выдачу. Кнопка «Сбросить фильтры» возвращает все комментарии.

Пользователь и мероприятие объединяются через AND. Сначала сервер выбирает комментарии выбранного автора и/или мероприятия, затем ограничивает период последними 24 часами и только после этого выбирает последние 10. Без автора и мероприятия ограничения применяются ко всем комментариям. Оба ограничения можно включить одновременно. Скрытые комментарии остаются доступны администратору.

`GET /api/v1/admin/comments` сохраняет `eventId`, `page`, `size` и принимает дополнительные необязательные параметры:

| Параметр | Значение |
| --- | --- |
| `authorId` | UUID автора |
| `latest` | `true`: последние 10 после остальных фильтров; `total` и все страницы вместе ограничены десятью |
| `last24Hours` | `true`: `createdAt >= серверное время − 24 часа` |

По умолчанию флаги выключены. Административный список отсортирован по `createdAt DESC, id DESC`; публичное обсуждение сохраняет порядок от старых сообщений к новым. Проверка ADMIN выполняется на сервере до доступа к фильтруемым данным. Новых таблиц и миграций не требуется; параметры добавлены в OpenAPI и generated-типы frontend.

Проверки: `mvn -o -B -ntp verify` — 62 теста H2 в исходном изменении API; backend при доработке интерфейса не менялся; целевые `moderation.test.tsx` и `moderation-core.test.ts` — 38 Vitest; `lint`, `typecheck`, `build`, `api:check` и `scripts/check_contract.py`. Java Playwright `admin-comment-filters.spec.ts` — 4 сценария на 320/375/768/1440 px с временной H2: видимые подсказки по одной букве, выбор обоих фильтров, быстрое включение обоих ограничений, последние сообщения в правильном порядке, отсутствие другого автора, восстановление после reload, очистка фильтров и отсутствие горизонтального скролла и одинаковые координаты/высота полей на 768/1440 px. Дополнительный Vitest проверяет запрет поиска пользователя по имени, ввод @никнейма, клавиатуру, отсутствие совпадений, восстановление после HTTP 503 и снятие одного фильтра с сохранением другого. Скриншоты панели и подсказок на мобильной и большой ширине просмотрены. Граница ровно 24 часа, неизвестный автор, неверные параметры, гость и обычный пользователь проверены на backend. PostgreSQL и полные браузерные наборы в этой задаче не запускались.

Кнопка «Применить фильтры» проверена в целевых Vitest и Java Playwright: выбор пользователя/мероприятия и флаги до нажатия не меняют выдачу и URL; после нажатия все условия применяются вместе. Крестик выбранного фильтра также меняет черновик; «Сбросить фильтры» сразу очищает и черновик, и применённые условия.
