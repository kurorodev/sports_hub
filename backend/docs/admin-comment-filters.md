# Фильтры комментариев администратора

В `/admin?section=comments` доступны поиск и выбор пользователя по никнейму, поиск и выбор мероприятия по названию, «Последние 10 комментариев» и «За последние 24 часа». Мероприятия в списке выбора доступны постранично. Фильтры включаются сразу, сохраняются в URL и восстанавливаются после перезагрузки; изменение условий сбрасывает страницу комментариев. Кнопка «Сбросить фильтры» возвращает все комментарии.

Пользователь и мероприятие объединяются через AND. Сначала сервер выбирает комментарии выбранного автора и/или мероприятия, затем ограничивает период последними 24 часами и только после этого выбирает последние 10. Без автора и мероприятия ограничения применяются ко всем комментариям. Оба ограничения можно включить одновременно. Скрытые комментарии остаются доступны администратору.

`GET /api/v1/admin/comments` сохраняет `eventId`, `page`, `size` и принимает дополнительные необязательные параметры:

| Параметр | Значение |
| --- | --- |
| `authorId` | UUID автора |
| `latest` | `true`: последние 10 после остальных фильтров; `total` и все страницы вместе ограничены десятью |
| `last24Hours` | `true`: `createdAt >= серверное время − 24 часа` |

По умолчанию флаги выключены. Административный список отсортирован по `createdAt DESC, id DESC`; публичное обсуждение сохраняет порядок от старых сообщений к новым. Проверка ADMIN выполняется на сервере до доступа к фильтруемым данным. Новых таблиц и миграций не требуется; параметры добавлены в OpenAPI и generated-типы frontend.

Проверки: `mvn -o -B -ntp verify` — 62 теста H2; целевые `moderation.test.tsx` и `moderation-core.test.ts` — 37 Vitest; `lint`, `typecheck`, `build`, `api:check` и `scripts/check_contract.py`. Java Playwright `admin-comment-filters.spec.ts` — 2 сценария на 375/1440 px с временной H2: выбор обоих фильтров, оба ограничения, последние сообщения в правильном порядке, отсутствие другого автора, восстановление после reload, очистка фильтров и отсутствие горизонтального скролла. Граница ровно 24 часа, неизвестный автор, неверные параметры, гость и обычный пользователь проверены на backend. PostgreSQL и полные браузерные наборы в этой задаче не запускались.
