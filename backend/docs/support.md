# Поддержка и жалобы

`features/support` создана от master; `fix/admincomment` не изменялась и не включена в эту работу.

## Возможности

- HELP: помощь; BUG: ошибка; IDEA: предложение; VENUE_SUGGESTION: новая площадка; COMMENT_REPORT: жалоба на комментарий.
- Приватное обращение с заголовком, подробностями, перепиской и историей статусов/приоритетов.
- Колокольчик: новое обращение/жалоба всем администраторам; ответ и изменение статуса автору; дополнение от пользователя администраторам. Автор действия не уведомляет сам себя.
- Общая очередь ADMIN: поиск, фильтры категории/статуса, пагинация. При ответе или изменении администратор назначается специалистом; другой администратор может продолжить работу.
- Приоритеты NORMAL / HIGH / URGENT меняет только ADMIN. Очередь сортируется по последнему обновлению; приоритет показан в карточке/деталях.

## Права и переходы

Чтение/переписка — только автору и ADMIN. Постороннему detail/reply/update/messages возвращают 404; личный список содержит только свои обращения. Общая очередь требует ADMIN. Сессия обязательна, POST/PATCH требуют CSRF. Author, assignedTo, роль ответа и снимок комментария назначает сервер; подмена дополнительных полей отклоняется.

Статусы: OPEN, IN_PROGRESS, WAITING_USER, RESOLVED, CLOSED. Администратор может выбрать любой статус. Ответ администратора переводит активное обращение в WAITING_USER, ответ пользователя — в OPEN. Пользователь может закрыть своё обращение или повторно открыть RESOLVED/CLOSED. В завершённое обращение нельзя писать до повторного открытия (409). Изменения статуса/приоритета остаются системными сообщениями; повторное назначение того же состояния не создаёт уведомлений.

Создание сериализуется блокировкой пользователя, изменения/ответы — блокировкой обращения. При закрытии/открытии жалобы также блокируется автор и меняется active_comment_id. Уникальность `(author_id,active_comment_id)` запрещает две активные жалобы одного пользователя на один комментарий. Данные и уведомления фиксируются одной транзакцией.

## Жалобы и площадки

В обсуждении вошедший пользователь нажимает «Пожаловаться». Причины: SPAM, ABUSE, UNSAFE, OTHER. Сервер проверяет видимость комментария и доступ к событию, сохраняет ID комментария/события, текст и имя автора на момент жалобы. Скрытый/недоступный комментарий — 404, повторная активная жалоба — 409. Автор комментария не получает жалобу и не узнаёт заявителя через API поддержки.

Жалоба не скрывает комментарий автоматически. Администратор переходит из обращения к обычной модерации обсуждения, проверяет сообщение и скрывает его с причиной. Приватная цитата остаётся после скрытия; администратор отвечает заявителю и завершает обращение.

VENUE_SUGGESTION требует название (title), город и адрес. В подробностях пользователь описывает спорт, доступность и условия. Администратор открывает предложение, проверяет название, выбирает необязательный вид спорта, уточняет адрес и обязательную для публикации точку. Кнопка «Добавить площадку и решить обращение» создаёт площадку в общем списке карты, сохраняет publishedVenueId, назначает администратора, переводит обращение в RESOLVED и уведомляет автора. В обращении появляется ссылка «Открыть добавленную площадку».

Обычная смена статуса на CLOSED/RESOLVED не создаёт площадку: это позволяет завершить отказ или дубликат. Одобрение доступно и для ранее закрытых обращений без publishedVenueId. Публикация, системное сообщение и уведомление выполняются одной транзакцией под блокировкой обращения; повторный запрос возвращает уже связанную площадку без дубля. Ошибка в адресе/координатах или существующий дубликат оставляют обращение неизменным. Публикация проверенного администратором предложения не ограничена обычной пользовательской квотой создания площадок.

Дополнительно можно указать точку на карте или выбрать подсказку адреса. Необязательные venueLatitude/venueLongitude передаются парой в диапазонах ±90/±180, сохраняются в обращении и доступны автору/ADMIN на мини-карте после reload. Ручной ввод без точки остаётся доступен; при недоступном геокодере введённый адрес сохраняется при выборе точки. V7 добавляет nullable-координаты и ограничение целостности без изменения старых обращений.

## API и хранение

| Метод | Путь | Результат |
| --- | --- | --- |
| GET / POST | `/support/tickets` | Свои обращения / создание |
| GET | `/admin/support/tickets` | Общая очередь, ADMIN |
| GET / PATCH | `/support/tickets/{ticketId}` | Чтение / статус и приоритет |
| GET / POST | `/support/tickets/{ticketId}/messages` | История / ответ |
| POST | `/support/tickets/{ticketId}/venue` | ADMIN: VenueCreate → SupportTicket со ссылкой на созданную площадку |

Списки: page ≥ 0, size 1–100, по умолчанию 20. История — новые первыми; UI собирает хронологический порядок с загрузкой ранних сообщений. Списки обращений принимают q (до 160), status, category. Неверные enum/UUID и пустой PATCH — 400. Заголовок 3–160, подробности 10–5000, сообщение 1–5000 после trim. Город до 120, адрес до 300. Поля комментария допустимы только для жалобы, адрес — только для площадки.

Лимиты: до 10 обращений в скользящий час на пользователя, до 60 сообщений в час на пользователя в одном обращении; превышение — 429. Файлы, email и внешние helpdesk-интеграции не реализованы. V6 добавляет support_tickets/support_messages, FK и индексы, сохраняя прежние данные. V8 добавляет nullable-связь published_venue_id с площадкой и ограничение уникальности. История поддержки не ограничивается 30-дневным окном колокольчика.

## Ручная проверка

1. Пользователем открыть `/support` через спасательный круг в шапке, создать вопрос или предложение площадки.
2. Администратором открыть уведомление или `/support?view=queue`, ответить, изменить статус/приоритет.
3. Автором открыть уведомление, проверить ответ после reload, дополнить, закрыть и повторно открыть.
4. В обсуждении отправить жалобу; администратором перейти к модерации, скрыть комментарий и ответить в обращении. Цитата остаётся; посторонний не читает обращение.
5. В предложении площадки администратором проверить поля и точку → «Добавить площадку и решить обращение» → открыть добавленную площадку на карте. Автор видит уведомление и ту же ссылку после reload. Для ранее закрытого предложения используется та же кнопка.

Опрос: открытое обращение — 10 секунд, список — 15, колокольчик — 30. MSW эмулирует те же сценарии; изоляцию и блокировки обеспечивает Java/PostgreSQL. Результаты и ограничения проверок — [frontend QA](../../frontend/docs/QA.md).
