## HTTP smoke с PostgreSQL

Подтверждены:

1. Новый вид спорта, создание/поиск события другим пользователем, защита владельца.
2. Запрет публикации до допуска организации, одобрение и отказ с причиной, публикация одобренной организации.
3. OPEN → CONFIRMED, видимость участника, запрет дубля.
4. APPROVAL → PENDING → CONFIRMED/REJECTED, запрет решения администратору.
5. Вопрос без записи, ответ автора, скрытие отдельного комментария.
6. Снятие публикации, причина для ранее зарегистрированных, отсутствие в каталоге и запрет прямой записи.
7. Автоматическая обработка очереди с сохранением лимита.
8. Уникальность Direct, приватность, членство и выход из Community.

Прямой доступ к Docker и localhost пользовательской машины из изолированной сессии агента остаётся недоступен. Результат запуска подтверждён сохранёнными логами команд, выполненных пользователем в обычном терминале, и успешным HTTP smoke, а не собственным curl из изолированной сессии.

## Исправленные проблемы

При первом реальном прогоне CSRF сбрасывался после первого запроса. Теперь демовход сохраняет стандартный SecurityContext в HttpSession до выдачи нового CSRF; собственный фильтр отложенной авторизации удалён. Выход очищает контекст и инвалидирует сессию. Регрессионный тест проверяет несколько запросов с одним токеном, отказ с неверным токеном и выход. CSRF-защита не отключена.

Для тестов выбран Mockito subclass mock maker, чтобы отсутствие динамического Java-agent attachment не мешало интеграционным проверкам. Сервисы и БД не подменяются.

Локальный запуск больше не повторяет Maven внутри Docker: JAR собирается на компьютере, runtime-образ копирует готовый артефакт. Основной Dockerfile сохраняет отдельную возможность сборки из исходников с кешем Maven. Повторный запуск готового JAR: `bash scripts/start-local.sh --skip-build`.

## Что ещё не проверено

- Полный профиль `mvn -Ppostgres-it verify` с Testcontainers: не запускался из-за отсутствия доступа к Docker daemon в сессии агента. Успешный HTTP smoke на PostgreSQL не подменяет его конкурентные проверки на этом сервере.
- Frontend, браузерные e2e, адаптивность, публичный HTTPS-деплой и нагрузочные испытания. Поставка содержит backend.
- Совместное ревью черновика OpenAPI. У POST `/conversations` описание требует HTTP 200 для существующего Direct, но в responses исходного YAML указан только 201. Реализация возвращает описанные 200/201; источник оставлен без изменений, подробности в decisions.md.
