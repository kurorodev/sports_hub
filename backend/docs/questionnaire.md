# Анкета пользователя и рекомендации

После регистрации нового аккаунта показывается необязательная анкета. Для существующих аккаунтов и демопользователей автоматический опрос не включается. Пропуск сохраняется на сервере и не сбрасывается после входа, смены устройства или перезагрузки. Из собственного профиля анкету можно открыть в любой момент.

Два шага: город и 1–10 интересующих видов спорта; затем уровень в каждом выбранном виде спорта и удобное время. Анкета обновляет существующие поля профиля `city`, `sportsPreferences`, `preferredTime`, сохраняя имя, никнейм, описание, аватар и спортивные роли. Используется тот же каталог видов спорта, что и при создании мероприятий.

## API

Все операции относятся только к текущему пользователю из cookie-сессии. Изменения требуют `X-CSRF-Token`.

- `GET /api/v1/me/questionnaire` — статус `PENDING | SKIPPED | COMPLETED`, время последнего сохранения и текущие ответы.
- `POST /api/v1/me/questionnaire` — атомарное сохранение и замена ответов. Формат:

```json
{
  "city": "Самара",
  "sportsPreferences": [{"sportId": "UUID из GET /sports", "level": "BEGINNER"}],
  "preferredTime": "EVENING",
  "timeZone": "Europe/Samara"
}
```

- `POST /api/v1/me/questionnaire/skip` — пропустить. Повторный пропуск не удаляет завершённую анкету и не меняет старые ответы.
- `GET /api/v1/events/recommended?size=6` — существующая объяснимая подборка. Без явного `city` используется город профиля. Только будущие опубликованные события; +50 за любимый спорт, +20 за подходящий уровень, +20 за удобное время, +10 за доступные места. Время определяется в часовом поясе браузера, сохранённом вместе с анкетой; для старых профилей используется UTC. Сначала наибольший балл, затем ближайшее начало и UUID. Другие виды спорта города могут попадать ниже в выдачу; подборка не гарантирует свободное место на момент записи.

Статус анкеты, часовой пояс и дата заполнения не добавляются в публичный профиль. Повторное формирование требует подтверждения в интерфейсе. До успешного сохранения прежние ответы и подборка действуют; отмена, Escape и закрытие формы их не меняют. Если мероприятий нет, показывается честное пустое состояние; ответы остаются сохранены, выдача рассчитывается заново при следующей загрузке.

## Миграции

`V12__user_questionnaire.sql` добавляет статус, дату заполнения и часовой пояс в `users`. В ветку включены неизменённые V10/V11 из `fix/adminpanel`: эти миграции уже применены в локальной базе ручного тестирования и должны оставаться доступными Flyway. Новая анкета не меняет поведение администрирования категорий. Данные и том PostgreSQL сохраняются.

## Проверка вручную

1. Зарегистрировать нового пользователя: анкета появляется по центру поверх исходного места назначения, в том числе при регистрации перед созданием встречи.
2. Нажать «Позже» или «Пропустить, заполню позже», перезагрузить страницу: анкета не открывается повторно.
3. Открыть свой профиль → «Сформировать рекомендации» → заполнить оба шага. Проверить интересы и подборку после перезагрузки.
4. Нажать кнопку ещё раз: подтверждение «Ваши рекомендации уже сформированы», «Да» и красная «Отмена».
5. Отмена сохраняет прежнюю подборку. «Да» открывает анкету с текущими ответами; после сохранения новые предпочтения видны в профиле.
6. Проверить второй аккаунт: ответы первого пользователя не переносятся. Без сессии собственная анкета недоступна; без CSRF запись запрещена.

- `mvn verify`: 82 теста, включая регистрацию, пропуск, повторное заполнение, валидацию, CSRF, изоляцию пользователей и сортировку по времени анкеты.
- `PostgresQuestionnaireTest`: 3 теста на отдельном PostgreSQL с миграциями V1–V12. Рабочая база в этих проверках не использовалась.
- Frontend: production-сборка, ESLint изменённых файлов, 44 проверки профиля.
- Chromium: 5 сценариев на 375/1440 px, включая красную отмену, сохранение после перезагрузки, старый вход по паролю и сохранение перехода к созданию встречи. Снимки анкеты и подтверждения просмотрены.
- Штатная проверка OpenAPI: 76 операций, enum и ресурсные схемы согласованы; сгенерированные TypeScript-типы актуальны.
