# Логика рекомендаций

`GET /api/v1/events/recommended` рассчитывает подборку для текущего участника. Это детерминированные правила, без внешнего AI, платных сервисов и обучения на вымышленных данных. Администратору подборка недоступна (403).

## Отбор

- Только опубликованные мероприятия с началом строго в будущем и действующей категорией спорта.
- Исключаются мероприятия пользователя и его организаций, заполненные встречи и любые мероприятия с его прежней регистрацией (включая отменённую или отклонённую). Они доступны через «Мои мероприятия» или каталог.
- По умолчанию используется город профиля, либо явно переданный `city`. Регистр, пробелы, `ё/е`, префиксы `г.` и `город` нормализуются. Это не поиск по похожим названиям. `includeOtherCities=true` снимает ограничение; без заданного города поиск также общий.
- При заполненных интересах по умолчанию показываются только выбранные виды спорта. `includeOtherSports=true` добавляет остальные, сохраняя приоритет любимых. Без интересов действует общая подборка доступных мероприятий.
- Старые идентификаторы категорий приводятся к актуальным через `canonicalId`. Если активность в категории «Другое» названа точно как существующий спорт (например, «ФУТБОЛ»), она учитывается как этот спорт. Поиск подстроки в названии мероприятия или описании не используется. Выбор самой категории «Другое» сохраняет интерес ко всем таким активностям.
- Необязательный приватный `age` пользователя сопоставляется только с явно заданными `recommendedMinAge` / `recommendedMaxAge` встречи. Границы включительны. Несовпадающий диапазон исключает встречу из рекомендаций; неизвестный возраст или отсутствие границ ничего не исключает. Каталог и запись не ограничиваются возрастом. Удалить возраст можно сохранением `null`.

Возраст не определяет интерес к спорту, здоровье или физические возможности. Например, 60-летний пользователь, выбравший баскетбол, получает подходящие баскетбольные встречи. Нельзя достоверно вывести возрастную аудиторию из одного названия спорта; старые мероприятия без возрастных ориентиров остаются доступными.

## Ранжирование

| Сигнал | Баллы | Причина в ответе |
| --- | ---: | --- |
| Выбранный спорт | 60 | `FAVORITE_SPORT` |
| Уровень совпал или мероприятие подходит любому уровню | 15 | `SUITABLE_LEVEL` |
| Совпало явно выбранное время | 10 | `PREFERRED_TIME` |
| Совпал явно указанный возрастной ориентир | 10 | `SUITABLE_AGE` |
| Доступна запись | 5 | `AVAILABLE_SPOTS` |

Любимый спорт всегда выше любого невыбранного: остальные сигналы вместе дают не более 40 баллов. Несовпадающий уровень не запрещает рекомендацию, но не даёт бонуса. Максимум — 100 баллов; число является внутренним рейтингом, а не вероятностью участия или процентом пригодности.

Время определяется по часовому поясу сохранённой анкеты: утро 06–12, день 12–18, вечер 18–24. Ночь 00–06 не считается вечером. `ANY` не добавляет фиктивного бонуса за удобное время. Старые профили используют UTC.

Сортировка: баллы по убыванию, начало по возрастанию, UUID по возрастанию. `page` / `size` применяются **после** фильтрации и сортировки. Интерфейс выводит по шесть карточек с переключением страниц, поэтому остальные совпадения не теряются. Смена области поиска возвращает первую страницу.

## Обновление и границы

Подборка пересчитывается на сервере при запросе, интерфейс обновляет её после сохранения анкеты, изменения предпочтений или записи/отмены участия, при возврате в окно и раз в 30 секунд. Остаток мест может измениться до записи: окончательное решение принимает транзакционная операция регистрации.

Приватный возраст возвращается только через `/me/questionnaire`, не через публичный профиль. В создании и редактировании мероприятия границы возраста необязательны, целые 1–120; нижняя не больше верхней. В карточке мероприятия диапазон виден как ориентир, а не запрет участия. Миграция `V16` не меняет существующие ответы или мероприятия.

Количество участников загружается одной групповой выборкой; DTO строятся только для запрошенной страницы. Текущая реализация ранжирует список будущих опубликованных мероприятий в памяти — для большого каталога можно перенести отбор и оценку в SQL, сохранив эти правила. Расстояние, история просмотров, здоровье и поведение других людей не угадываются и не используются.

## Регрессионные проверки

`RecommendationTest` проверяет любимый футбол, пользовательские названия, приоритет интересов, города, пагинацию, возраст без стереотипов и запрета записи, заполненные/собственные/прошедшие мероприятия, прежние регистрации, часовой пояс, приватность и валидацию. `PostgresRecommendationTest` повторяет сценарии на PostgreSQL с Flyway. Браузерный сценарий `recommendations.spec.ts` проверяет анкету и управление подборкой на мобильном и широком экране.
