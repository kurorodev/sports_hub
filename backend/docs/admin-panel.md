# Кабинет администратора

Администратор использует модерацию организаций, мероприятий и комментариев, очередь поддержки, а также справочник видов спорта. Создание мероприятий и организаций, запись и очередь участия, публикация комментариев, пользовательское добавление площадок и оценка загруженности возвращают 403. Административное создание проверенной площадки через очередь поддержки сохраняется. Старые личные события не дают администратору права организатора.

В профиле остаются имя, никнейм, личные сведения и аватар. Спортивные роли, интересы, удобное время и рейтинг скрыты. Сервер запрещает непустые спортивные настройки; пустые значения совместимы с общей формой профиля. USER и представители организаций продолжают обычные сценарии создания и участия.

## Категории и фото

- `POST /api/v1/admin/sports`: JSON `{name, imageData?}`. Название 2–80 символов, пробелы нормализуются, дубликаты без учёта регистра запрещены. Требуются ADMIN, сессия и CSRF.
- `PUT /api/v1/admin/sports/{sportId}/image`: JSON `{imageData}`; null удаляет фото, строка загружает или заменяет. Требуются ADMIN и CSRF.
- `GET /api/v1/sports/{sportId}/image`: публичные PNG/JPEG, 404 без фото. Относительный `Sport.imageUrl` присутствует в справочнике и вложенной категории мероприятия. Без фото используются прежние иллюстрации. URL содержит версию для обновления карточек после замены.

`imageData` — Data URL PNG/JPEG. Проверяются реальные байты, формат, размер до 2 МиБ и размеры до 4096×4096. ImageIO заново кодирует изображение без исходных метаданных. Фото хранится в PostgreSQL, внешнего хостинга и локального каталога файлов не требуется. Официальный справочник не переписывается: миграция V10 расширяет ограничение `sports_fixed_catalog` отдельным признаком дополнительных категорий администратора. `isCustom=true` по-прежнему обозначает только «Другое», код ВРВС у дополнительных категорий отсутствует.

В интерфейсе категории доступны на `/admin?section=sports`: создание с необязательным предпросмотром, поиск, замена и удаление фото. Список выводится по 12 карточек с кнопкой следующей порции. Изображения используются и в карточках встреч, и в выборе спорта.

## Фильтры и развёртывание

Организации: поиск по названию/описанию и статус заявки. Мероприятия: поиск по названию/описанию и статус публикации. Форма, отступы и кнопки повторяют фильтры комментариев. Поля применяются вместе кнопкой «Применить фильтры», сброс очищает поиск/статус и возвращает первую страницу. Повторное применение обновляет выдачу.

В Nginx лимит тела увеличен до 4 МиБ для JSON с base64-фото. Внешний reverse proxy также должен пропускать не менее 4 МиБ. Web Dockerfile собирается с корнем репозитория как build context: это включает общий `branding.json`; соответствующий compose override обновлён, локальные секреты и зависимости исключены из контекста.

## Проверки

`mvn verify`: 81 тест. PostgreSQL/Testcontainers: 10 тестов управления категориями, фото, административных прав и поддержки. Vitest: 83 теста модерации, организаций, профиля, справочника, карты и основных потоков. Playwright с настоящими Java/PostgreSQL: два комплексных сценария на 375/1440 px, сохранение фото после перезагрузки, использование фото пользователем, профиль администратора, запреты в интерфейсе и применение/сброс фильтров. Typecheck, production build, api:check, проверка контракта и compose проходят.

Общий ESLint не содержит ошибок, но останавливается на прежнем предупреждении `Textarea.tsx:36` (`react-hooks/exhaustive-deps`), компонент не менялся. Проверка Docker-сборки web зависит от доступа к Docker Hub; при выполнении задачи registry отвечал TLS-таймаутом. Физические устройства и внешний production-сервер не проверялись.
