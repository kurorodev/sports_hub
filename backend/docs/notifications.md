# Личные уведомления

Согласовано с владельцем продукта 20.10.2026: колокольчик и модальное окно, причины модерации только в личных уведомлениях адресата. S2/S4/S6 сохраняют серверные статусы и аудит; способ доставки причин изменён по этому решению.

## Получатели

| Событие | Кто получает |
| --- | --- |
| OPEN / APPROVAL / очередь / отмена / решение | Пользователь, чей статус изменился |
| Новая заявка, запись или очередь | Организатор, кроме своей записи |
| Одобрение/отказ организации | Её создатель — текущий уполномоченный представитель |
| Публикация мероприятия | Организатор |
| Снятие публикации | Организатор с причиной; активные PENDING/CONFIRMED/WAITLISTED участники без причины |
| Скрытие комментария | Только автор с причиной |
| Изменение времени или места | Активные заявители/участники, кроме организатора |
| Начало в течение часа | Организатор и только CONFIRMED участники |
| Упоминание в публичном обсуждении | Упомянутые пользователи, кроме самого автора; один раз на комментарий |

Для события организации получатель — `organizations.created_by`: дополнительных управляющих ролей текущая модель не содержит. Упоминание не предоставляет доступ к закрытым ресурсам.

## Контракт и хранение

- `GET /api/v1/me/notifications?page=0&size=20`: `NotificationPage`, новые сверху, `unreadCount` по всему 30-дневному окну, серверный `asOf`.
- `POST /api/v1/me/notifications/{notificationId}/read`: идемпотентное чтение, сохранённый `readAt`.
- `POST /api/v1/me/notifications/read-all` с `{through: asOf}`: 204; более новые уведомления остаются непрочитанными. Будущая граница ограничена серверным временем.

Обязательны сессия и CSRF для POST. Чужая запись и запись старше 30 дней дают 404, включая ADMIN. Размер страницы 1–100. `reason` и текст — серверные снимки; frontend отображает их как текст. Ссылки ограничены внутренними событиями и страницей своей организации. Прочитанное сохраняется в PostgreSQL после reload, переключения аккаунта и перезапуска Java.

V5 создаёт таблицу/индексы и переносит существующие причины снятия событий/скрытия комментариев соответствующим владельцам без удаления исходных данных. Окно ленты и счётчика — последние 30 дней; старые записи не выдаются этим API. Автоматического удаления истории миграция не выполняет. `Event.moderationReason` оставлен для совместимости, помечен deprecated и всегда null, в том числе для администратора. Аудит модерации сохраняется.

У `COMMENT_HIDDEN` поле `commentText` хранит полный исходный текст комментария (до 2000 символов), отдельно от названия встречи и причины. В личном уведомлении автора он показан блоком «Ваш комментарий», включая переносы строк. Текст выводится без HTML-разметки; скрытый комментарий по-прежнему не возвращается обычным пользователям в публичном обсуждении. V9 заполняет `commentText` и у существующих уведомлений по сохранённому ID комментария и его автору, сохраняя причины, даты и отметки прочтения. Поле необязательное/nullable для совместимости; остальные типы уведомлений его не используют.

## Доставка

Изменение статуса и уведомление фиксируются одной транзакцией. Неуспешное действие не создаёт уведомления. Организация, регистрация, очередь и снятие события используют существующие блокировки; скрытие комментария блокирует сначала событие, затем перечитывает заблокированный комментарий.

Серверный планировщик проверяет опубликованные события каждую минуту, независимо от открытого браузера. Напоминание выдаётся в интервале `(now, now + 1 hour]`. На событии удерживается та же блокировка, что при записи/редактировании/модерации; уникальный `(recipient_id,dedupe_key)` защищает от повторов, в том числе после перезапуска. Перенос начала создаёт новую версию напоминания. Для завершившихся/снятых событий, PENDING, WAITLISTED и CANCELLED напоминания не создаются.

Настройки: `app.notifications.scheduling` (по умолчанию true), `app.notifications.interval-ms` (60000), `app.notifications.initial-delay-ms` (10000). В unit/integration профиле расписание отключено, сервис вызывается тестом. Если backend был выключен весь час перед встречей, просроченное напоминание не рассылается.

Frontend опрашивает API каждые 30 секунд в активной вкладке и обновляет ленту при открытии окна. Собственные создание/запись также инвалидируют кэш уведомлений. При смене аккаунта приватный кэш удаляется. MSW эмулирует те же DTO, права и переходы; напоминания в mock вычисляются при опросе, не являются Java-интеграцией.

## Проверки

Backend: позитивные/негативные/граничные проверки уведомлений на H2 и PostgreSQL; обе ветви APPROVAL, CSRF, чужое чтение, очередь/отмена, окно 30 дней, пагинация, сохранение `readAt`, граница read-all, личные причины, организация, mentions и дедупликация напоминаний. Миграционные проверки отдельно подтверждают перенос старых причин пользователя/организации/комментария на H2/PostgreSQL. Browser QA и точные результаты — [frontend QA](../../frontend/docs/QA.md).
